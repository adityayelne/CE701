# CompilerLab — Educational Compiler Construction Learning Lab

**CompilerLab** is an interactive, AI-assisted compiler construction platform designed for computer science students and educators. It visualizes each foundational stage of a C compiler—lexical analysis, abstract syntax trees, symbol tables with lexical scoping, and intermediate three-address code generation—while providing safe, educational diagnostics and repair diffs.

---

## 🏛️ Compiler Pipeline Architecture: The Shared AST

CompilerLab strictly enforces a **single, shared-AST compilation pipeline**:

```
                  ┌──────────────────────┐
                  │ C Source Code Input  │
                  └──────────┬───────────┘
                             │
                             ▼
                  ┌──────────────────────┐
                  │    lexer.py          │  (Scanner & Tokenizer)
                  └──────────┬───────────┘
                             │ Token stream with (line, col, regex rules)
                             ▼
                  ┌──────────────────────┐
                  │    parser.py         │  (Recursive Descent Parser)
                  └──────────┬───────────┘
                             │
     ┌───────────────────────┴───────────────────────┐
     │ Canonical Shared Abstract Syntax Tree (ASTNode)
     ▼                                               ▼
┌───────────────────────────┐         ┌───────────────────────────┐
│     symbol_table.py       │         │      ir_generator.py      │
│ (Hierarchical Scope Tree, │         │ (Three-Address Code,      │
│  Offset, Type Resolution) │         │  Quadruples, Basic Blocks)│
└───────────────────────────┘         └───────────────────────────┘
```

### Strict Architectural Invariants
1. **Single Source of Truth**: The `CParser` creates the canonical `ASTNode` hierarchy. Downstream passes (`symbol_table.py` and `ir_generator.py`) traverse this exact AST.
2. **No Ad-Hoc Source Scanning**: Downstream semantic analysis and IR generation never use raw regex scanning or re-lex the source code.
3. **Parser-Validated AI Repairs**: Any proposed fix generated by the diagnostic engine is re-parsed through the full compiler pipeline (`LexicalAnalyzer` and `CParser`). If residual errors exist, it is explicitly flagged as unverified; validation is never fabricated.
4. **Separation of Validity Stages**: Syntactic validity, static semantic validity, and AI repair suggestions are strictly segregated in the data model and UI.

## 🚀 Key Features

- **Multi-Pass Compiler Visualizer**:
  - **1. Lexical Analysis**: Interactive token stream, category filters (Keywords, Identifiers, Literals, Operators, Delimiters), and formal regex rules.
  - **2. Symbol Table**: Scoped symbol breakdown (`global`, `function`, `block`), nesting depths, line declarations, estimated memory sizes in bytes, and stack offsets.
  - **3. Abstract Syntax Tree (AST)**: Expandable/collapsible interactive node hierarchy with a real-time attribute inspector and node search.
  - **4. Intermediate Code (TAC)**: Linear Three-Address Code with temporary registers (`t0`, `t1`, ...), branch labels (`L0`, `L1`), Quadruples table `(op, arg1, arg2, result)`, and Basic Blocks with Control Flow Graph (CFG) transitions.
- **Educational Concept Explainer**:
  - Interactive guide exploring the 4 core compiler construction phases with formal grammar patterns, architectural principles, and frequent implementation pitfalls.
- **AI Compiler Diagnostics & Side-by-Side Diff**:
  - Explains syntax and semantic errors with source line numbers, context, and compiler rules.
  - Displays a clean unified diff comparing original vs. corrected code.
  - 1-click "Copy Corrected Code" and explicit "Apply Fix to Editor" controls (preventing accidental source overwrite).

## 💻 Local Setup & Execution Instructions

### Prerequisites
- Node.js (v18+) and npm
- Python (3.10+) with pip

### 1. Backend Setup & Run

Activate the environment from the project root (`F:\cc`):

```powershell
.\.venv\Scripts\Activate.ps1
```

To run the backend server, either:

**Option A (from inside `backend/`):**
```powershell
cd backend
uvicorn main:app --reload --port 8000
```

**Option B (from project root `F:\cc`):**
```powershell
uvicorn backend.main:app --reload --port 8000
```

The backend API will be live at `http://127.0.0.1:8000`. You can inspect the interactive OpenAPI documentation at `http://127.0.0.1:8000/docs`.

### 2. Frontend Setup

In a separate terminal:

```bash
cd frontend

# Install dependencies
npm install

# Start Vite development server
npm run dev
```

Open `http://127.0.0.1:5173` in your browser.

## 🔑 Groq API & Qwen 3.8 27B Configuration

CompilerLab integrates with **Groq** using the **`qwen/qwen3.8-27b`** model to provide high-speed, educational C syntax diagnosis and repair.

### 1. Obtain a Free Groq API Key
1. Visit the [Groq Console](https://console.groq.com/keys).
2. Sign in or create an account, then click **"Create API Key"**.
3. Copy your key (format: `gsk_...`).

### 2. Configure the Backend
In `backend/.env` (copy from `backend/.env.example` if needed):

```dotenv
LLM_PROVIDER=groq
GROQ_API_KEY=gsk_your_groq_api_key_here
GROQ_MODEL=qwen/qwen3.8-27b
```

### 3. Graceful Offline Operation
- If no Groq API key is provided, CompilerLab seamlessly runs using its built-in deterministic heuristic compiler repair engine.
- The server will always boot without errors even when no API keys are present.

---

## 🔒 Security & Educational Boundaries

- **No Arbitrary Code Execution**: CompilerLab parses, analyzes, and visualizes C code. User code is **never executed** or evaluated on the server.
- **No Unintended Overwriting**: Suggested repairs are shown in an isolated diff view. Source code in the editor is only modified when the user explicitly clicks "Confirm Apply".
- **Zero Hardcoded Secrets**: External LLM API keys are loaded via backend environment variables only and never leaked to the client. The application functions 100% offline if no external key is provided.
